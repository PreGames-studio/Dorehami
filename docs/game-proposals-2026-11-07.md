# پیشنهاد چهار بازی بعدی — ۲۰۲۶-۱۱-۰۷

> این سند **پیشنهاد** است، نه تعهد. هیچ‌کدام از این چهار بازی وارد `docs/ROADMAP.md` نشده تا
> کاربر یکی را تأیید کند؛ پس از تأیید، هر بازی یک بخش در نقشهٔ راه + یک پوشهٔ مستقل می‌گیرد.

## ۱. چهار فیلتری که پیشنهادها از آن رد شده‌اند

هر بازی برای این اپ باید هم‌زمان از این چهار دروازه بگذرد:

| دروازه | چرا |
|---|---|
| **روی یک گوشی قابل بازی باشد** (پاس‌دادن گوشی) | بلوتوث/هات‌اسپات امروز کد دارد ولی روی گوشی واقعی آزمایش نشده (`ROADMAP` §M5 🟡). بازی‌ای که تک‌گوشی کامل باشد، بدون ریسک منتشر می‌شود و اتاق بلوتوثی بعداً رویش سوار می‌شود |
| **قطعی و قابل بازپخش باشد** (سید + لاگ حرکات) | قانون اصلی پروژه: `GameSession` تابعی خالص از `(seed, action log)` است؛ بازی‌ای که به تاس/ساعت سیستم یا سرور نیاز دارد، با ADR-0003 نمی‌خواند |
| **فرهنگ دورهمی ایرانی + خوانایی ۴۵+/۶۰+** | بازار هدف کافه‌بازار، خانواده و سنین بالاتر: متن فارسی، اعداد فارسی، هدف لمس بزرگ، بدون شلوغی |
| **بدون بدهی حقوقی/محتوایی سنگین** | بازی با برند ثبت‌شده یا بانک محتوایی که مجوزش معلوم نیست، برای انتشار در کافه‌بازار ریسک است |

## ۲. چهار پیشنهاد (به ترتیب پیشنهادی اجرا)

### ۲.۱ اسم فامیل — بهترین نسبت ارزش به زحمت

| | |
|---|---|
| تعداد بازیکن | ۲ تا ۸ |
| حالت | تک‌گوشی (پاس‌دادن) و بعداً اتاق بلوتوثی |
| زمان هر دور | ۲ تا ۳ دقیقه |
| اطلاعات پنهان | ✅ جواب هر نفر تا پایان دور خصوصی است |

**چرا:** پرطرفدارترین بازی کاغذی مهمانی‌های ایران، بدون هیچ قطعه و تخته، و برای هر سنی. محتوا
نمی‌خواهد — فقط فهرست دسته‌ها (اسم، فامیل، شهر، حیوان، خوراکی، اشیا، گیاه…) و حروف الفبا.

**شکل موتور:** `LETTER` (حرف از `Rng`) → `WRITING` (تایمر از `Clock`) → `REVEAL` (امتیاز) → دور بعد.
جواب‌ها `GameAction` هستند، امتیاز یک تابع خالص روی همهٔ جواب‌های دور است (یکتا ۱۰، تکراری ۵، خالی ۰،
حرف اشتباه ۰). هیچ‌جای منطق به شبکه یا ساعت سیستم نیاز ندارد.

**کار اصلی:** صفحهٔ ورودی فارسی/RTL (کیبورد، پرش خودکار بین خانه‌ها، ذخیرهٔ نصفه‌کاره)، برگهٔ امتیاز،
حلقهٔ تایمر. موتور کوچک است؛ زحمت اصلی UI است، نه قواعد.

**تست‌های لازم:** ترتیب حروف با همان سید، امتیاز یکتا/تکراری/خالی/حرف‌اشتباه، اتمام تایمر،
نبود نشت جواب دیگران در view عمومی.

**ریسک:** کیفیت تایپ فارسی روی صفحه‌های کوچک؛ رفع با چیدمان تک‌ستونی و اندازهٔ قلم بزرگ.

---

### ۲.۲ مافیا (گردانندهٔ مافیا) — پرچم‌دار برند

| | |
|---|---|
| تعداد بازیکن | ۶ تا ۱۲ |
| حالت | تک‌گوشی، گوشی دور می‌گردد؛ اتاق بلوتوثی در فاز بعد |
| اطلاعات پنهان | ✅✅ این بازی *همه‌اش* اطلاعات پنهان است |

**چرا:** محبوب‌ترین بازی مهمانی ایران است و دقیقاً روی برند «دورهمی» می‌نشیند. اپ نقش **گرداننده**
را برمی‌دارد: پخش مخفی نقش‌ها، اجرای شب (قتل مافیا، نجات دکتر، استعلام کارآگاه)، رأی‌گیری روز، و
خواندن متن روایت فارسی. بحث و گفت‌وگوی بازیکنان بیرون از اپ می‌ماند — همان‌طور که در بازی واقعی هم هست.

**شکل موتور:** ترکیب نقش‌ها از `Rng` (با ترکیب‌های آماده: ۱ مافیا/۶ نفر … ۴ مافیا/۱۲ نفر)، فازهای
`ROLE_REVEAL` (هر نفر گوشی را می‌گیرد و نقش خودش را می‌بیند) → `NIGHT` → `DAY_VOTE` → `RESULT`.
هر شب: هر نقش فقط `privateView` خودش را می‌بیند؛ view عمومی فقط «شب شد/روز شد/چه کسی حذف شد».

**چرا با معماری فعلی می‌خواند:** مکانیزم `Emission.Private` و تست ساختاری «کلید خصوصی در view عمومی
نیست» از قبل وجود دارد و همین بازی سخت‌ترین آزمون آن است.

**کار اصلی:** جریان پاس‌دادن گوشی (handover) که نشت نکند، صفحهٔ شب با دکمه‌های نقش‌محور، برگهٔ رأی‌گیری
با ۱۲ صندلی، و متن روایت فارسی (بعداً صدا).

**تست‌های لازم:** پخش نقش با سید مشخص، نبود نشت نقش در view عمومی (سخت‌گیرانه، برای هر فاز)، شمارش
رأی و تساوی، پایان بازی (برد مافیا/شهر)، ترکیب نامعتبر (مثلاً ۱ مافیا برای ۴ نفر) رد شود.

**ریسک:** نیاز به ۱۲ صندلی در UI و بازبینی اتاق بلوتوثی برای بیش از ۴ نفر؛ برای نسخهٔ اول، تک‌گوشی
کافی است و ریسک را صفر می‌کند.

### ۲.۳ منچ — پوشش خانواده و سنین بالاتر

| | |
|---|---|
| تعداد بازیکن | ۲ تا ۴ |
| حالت | تک‌گوشی + بلوتوث/هات‌اسپات (مثل تخته نرد) |
| زمان | ۱۵ تا ۲۵ دقیقه (حالت سریع: ۱۰ دقیقه) |

**چرا:** شناخته‌شده‌ترین بازی رومیزی خانه‌های ایرانی؛ هر بچه و پدربزرگی قواعدش را می‌داند و یادگیری
نمی‌خواهد. تخته‌اش هم‌خانوادهٔ میز چوبی تخته نرد است که همین حالا در اپ داریم.

**شکل موتور:** تاس از `Rng` (نه `Random()`)، حرکت‌ها `GameAction`، بیرون‌آوردن مهره، زدن مهرهٔ حریف،
ورود به خانهٔ آخر. کاملاً قطعی و قابل بازپخش؛ بدون اطلاعات پنهان.

**کار اصلی:** تختهٔ ۱۵×۱۵ خوانا (اندازهٔ خانه و مهره برای لمس و برای چشم ۶۰+)، انیمیشن تاس و حرکت،
حالت «سریع» برای کوتاه‌کردن بازی.

**تست‌های لازم:** تاس قطعی با همان سید، قاعدهٔ ۶ برای خروج، زدن و برگشت به خانه، مسدود بودن مسیر،
پایان بازی، بازپخش با همان digest.

**ریسک:** شانس‌محور بودن؛ برای مخاطب بزرگسال باید با میز خوش‌ساخت و حالت سریع جبران شود. اگر
«تصمیم‌محور» می‌خواهیم، شطرنج و تخته نرد را داریم؛ منچ برای «خانواده» است، نه برای رقابت جدی.

### ۲.۴ کوییز دورهمی — ژانر دانش، با هزینهٔ محتوا

| | |
|---|---|
| تعداد بازیکن | ۲ تا ۶ |
| حالت | تک‌گوشی، نوبتی یا زودزنی |
| محتوا | بانک سؤال فارسی با منبع/مجوز مشخص |

**چرا:** شکاف ژانر را پر می‌کند: بازی‌های فعلی یا ورق‌اند یا تخته یا نمایشی؛ کوییز برای جمع‌های
خانوادگی و کسانی است که بازی کلمات/حرکت دوست ندارند. برای مخاطب ۴۵+ هم جذاب است.

**شکل موتور:** ترتیب سؤال‌ها از `Rng`، پاسخ‌ها `GameAction`، امتیاز تابع خالص (درست/غلط/زمان). موتور
کوچک است؛ **همهٔ زحمت روی محتواست**.

**چرا اینجا ارزان‌تر از بازی دیگر است:** همان خط تولید بانک واژهٔ پانتومیم قابل استفاده است
(`scripts/generate_pantohub_seed_v3.py` + `validate_pantohub_seed.py`: چانک‌های متنی، تولید قطعی،
اعتبارسنجی یکتایی و شمارش). فقط باید ستون «پاسخ درست + منبع» اضافه شود.

**تست‌های لازم:** ترتیب سؤال با سید، امتیاز، رد سؤال با پاسخ خالی/تکراری در بانک، نبود سؤال تکراری
در یک دور، اعتبارسنجی منبع.

**ریسک:** بدهی محتوایی. پانتومیم هنوز ۲٬۵۰۰ رکورد از هدف ۲۰٬۰۰۰ دارد؛ کوییز نباید همان دام را تکرار
کند. حداقل قابل انتشار: ۲٬۰۰۰ سؤال با منبع روشن و بازبینی فارسی.

## ۳. مقایسهٔ سریع

| بازی | ارزش برای برند | زحمت موتور | زحمت UI | زحمت محتوا | تک‌گوشی؟ | پیشنهاد |
|---|---|---|---|---|---|---|
| اسم فامیل | بالا | کم | متوسط | تقریباً صفر | ✅ | **اول** |
| مافیا | خیلی بالا | متوسط | متوسط | کم (متن روایت) | ✅ | **دوم** |
| منچ | متوسط-بالا | کم | زیاد (تخته/انیمیشن) | صفر | ✅ | سوم |
| کوییز | متوسط | کم | متوسط | زیاد (بانک سؤال) | ✅ | چهارم |

**ترتیب پیشنهادی:** اسم فامیل (سریع‌ترین بازی قابل‌دست‌دادن) → مافیا (پرچم‌دار) → منچ (خانواده) →
کوییز (وقتی بانک محتوا آماده بود).

## ۵. آنچه برای هر چهار بازی ثابت می‌ماند

* هر بازی **یک پوشهٔ مستقل**: `games/<id>/core` + `games/<id>/ui`؛ هیچ تغییری در `core/*` لازم نیست
  (قانون ۱ در `AGENTS.md`).
* چهار تست قرارداد برای هر بازی: بازی کامل/ربات، بازپخش با همان digest، نبود نشت اطلاعات پنهان،
  حالت‌های مرزی امتیاز.
* «تمام شد» یعنی `checkAll` سبز + APK ساخته‌شده + شاهد در نقشهٔ راه؛ نه «صفحه ساخته شد».
* برای هر چهار بازی، نسخهٔ اول **تک‌گوشی** است و اتاق بلوتوثی/آنلاین بعد از اثبات روی دستگاه
  واقعی (بند M5 نقشهٔ راه) وصل می‌شود.
