# دورهمی 🎲

اپ اندروید برای همهٔ بازی‌های دورهمی در یک جا: ورق (حکم)، نمایشی (پانتومیم)، فکری (شطرنج) و هر بازی
بعدی که اضافه شود.

| حالت بازی | چطور؟ | بدون اینترنت؟ |
|---|---|---|
| اتاق بلوتوثی | یک گوشی میزبان می‌شود، بقیهٔ نزدیک‌ها وصل می‌شوند | ✅ آفلاین |
| اتاق آنلاین با دوستان | کد اتاق روی سرور خودمان (VPS ایرانی) | ❌ |
| حریف تصادفی / تورنمنت | صف سرور | ❌ |

**وضعیت فعلی مخزن:** چهار بازی کامل به دکمه‌هایشان وصل‌اند — حکم (`games/hokm`، ۲/۳/۴ نفره با
ربات، بلوتوث و آنلاین، با صف رویداد/انیمیشن و گارد ضدتکرار)، شطرنج (`games/chess`، میز سه‌بعدی
OpenGL ES، ربات چهارسطحی، دونفرهٔ محلی، بلوتوث و هات‌اسپات آفلاین؛ آنلاین نمایشی)، پانتومیم
(`games/pantohub`، بانک واژهٔ محلی، دو حالت بازی) و تخته نرد (`games/backgammon`، قواعد کامل با
ربات قطعی و دونفرهٔ روی یک گوشی؛ آنلاین نمایشی). دکمه‌های
منچ، مونوپولی و مافیا برای توسعهٔ بعدی نمایش داده می‌شوند. فروشگاه و کیف‌پول سکهٔ آفلاین
برای آیتم‌های ظاهری، داخل منوی خود شطرنج قرار دارند؛ خرید بسته‌های سکه فعلاً نمایشی است. دژبان هنوز جای‌نگهدار است. آزمون و ساخت Gradle در
GitHub Actions انجام می‌شود (`.github/workflows/`)؛ ساخت محلی به JDK 17 و Android SDK نیاز دارد.
تصمیم‌ها و وضعیت واقعی در `docs/ARCHITECTURE.md`، `docs/adr/` و `docs/ROADMAP.md` ثبت می‌شود.

**حالت‌های پانتومیم:** حالت بازی یک‌بار پیش از ساخت بازی انتخاب می‌شود (سرعتی یا عادی) و همان
انتخاب به ویزارد شروع پاس می‌شود؛ پیکر تکراری داخل ویزارد وجود ندارد. در «سرعتی» تا پایان زمان
پشت‌سرهم واژه حدس زده می‌شود؛ در «عادی» پیش از هر نوبت سختی (و در صورت نیاز دسته) انتخاب می‌شود
و با یک پاسخ درست نوبت تمام می‌شود.

**محدودیت نسخهٔ فعلی:** بستهٔ شروع بانک اکنون ۲٬۵۰۰ رکورد فارسیِ دست‌چین‌شده و یکتا دارد
(۱٬۰۰۰ آسان، ۹۰۰ متوسط، ۶۰۰ سخت)؛ این فقط مرحلهٔ آزمایشی است و هدف ۲۰٬۰۰۰ رکورد معتبر هنوز
تکمیل نشده. ارتقای seed نسخهٔ دوم روی نصب
قبلی فقط واژه‌های غایب را اضافه می‌کند و رکوردهای موجود را بازنویسی نمی‌کند. بازی و بانک محلی‌اند؛
همگام‌سازی ابری تنظیم نشده است. شمارش و یکتایی seed با `scripts/validate_pantohub_seed.py` کنترل
می‌شود؛ دادهٔ ساختگی یا تکراری برای رسیدن به عدد هدف تولید نمی‌شود.

## ساخت و تست (خلاصه)

نیازمندی: JDK 17 + Android SDK (compileSdk 36). دیتابیس اختیاری است.

```bash
./gradlew checkAll            # همهٔ تست‌های JVM (چیزی که CI اجرا می‌کند)
./gradlew :app:assembleDebug  # ساخت APK: app/build/outputs/apk/debug/
./gradlew :server:run         # اجرای سرور روی http://localhost:8080

tools/jvm-check/run.sh        # بازبینی سریع پیش از push: کامپایل+تست ماژول‌های JVM بدون Gradle
```

`tools/jvm-check/run.sh` فقط لایه‌های JVM را می‌سنجد؛ Compose را کامپایل نمی‌کند. اگر امضای یک
composable را عوض کردی، همهٔ فراخوان‌ها را با `grep` پیدا کن؛ خطای نوع آن فقط در CI (یا یک
`./gradlew :app:assembleDebug`) دیده می‌شود.

روی ماشین کم‌حافظه:

```bash
./gradlew checkAll -Dorg.gradle.jvmargs="-Xmx1200m -XX:MaxMetaspaceSize=512m" \
  -Dkotlin.compiler.execution.strategy=in-process
```

## ساختار پوشه‌ها

```
core/protocol    پیام‌ها و قالب حرف‌زدن قطعه‌ها (بدون وابستگی)
core/gamesdk     قرارداد بازی: قواعد، موتور، قطعیت، رکورد قابل اثبات
core/session     چرخهٔ اتاق: لابی، نوبت، تایمر، ریسینک (مشترک بین آفلاین/آنلاین)
core/testkit     فیک‌های درون‌حافظه برای تست سریع
core/uikit       تم Compose، راست‌به‌چپ، اجزای مشترک رابط کاربری
transport/api    قرارداد «لوله» (ارتباط)
transport/nearby بلوتوث/وای‌فای دایرکت — بازی آفلاین
transport/hotspot اتصال مستقیم TCP روی هات‌اسپات/شبکهٔ محلی — بدون سرور
transport/online وب‌سوکت + صف حریف تصادفی
games/<بازی>/core  قواعد یک بازی (مستقل، مالک: یک نفر)
games/<بازی>/ui    صفحه‌های همان بازی
server           داور آنلاین: اتاق، صف، ذخیره و راستی‌آزمایی نتیجه
app              اپ اندروید: ناوبری، لابی، تنظیمات
tools            بازبینی محلی (jvm-check) و اسکریپت‌های داده/انتشار
docs             همین اسناد + تصمیم‌ها (ADR) + گزارش‌های اجرا
```

قانون اصلی: `games/*` به هیچ بازی دیگر وابسته نیست؛ هر بازی یک پوشهٔ قابل واگذاری است.
